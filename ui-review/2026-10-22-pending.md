## Pending items, ranked

### P1 — breaks a user flow on the target platform

1. **Linux uninstall confirmation silently does nothing without zenity/kdialog.**
   `LinuxShell.Confirm` (`src/DlsiteClient.Platform.Linux/LinuxPlatform.cs:438`) returns `false` when neither helper exists, which is the normal case on SteamOS/Arch. The uninstall then does nothing and shows nothing.
   Fix options: an in-app confirm dialog (Avalonia `Window.ShowDialog`), or declare zenity/kdialog as a package dependency and advertise it.
   Needs a requirements line either way.

2. **Sort order is ordinal, not kana.** `sortKey` in `src/DlsiteClient.App/Views/LibraryView.fs` casts strings to `IComparable`, so あ/ア/漢 do not collate the Japanese way.
   Fix: `StringComparer.Create(CultureInfo.GetCultureInfo("ja-JP"), true)` wrapped in the sort key.
   Blocker: must be proven under Native AOT (`net10.0-windows`, `TrimMode=partial`) that ICU data is present. Publish AOT on the Windows host or in the VM, then compare sort output.

3. **Settings values are untrusted.** Free-text numbers with silent clamping to defaults (`applyDownload`), no folder pickers for library/cache/log, and one debounce instance shared by every field (`SettingsView.fs`, `UiAsync.debounce`).
   gpt-6.1-sol voted for text validation with inline localized errors, and against `NumericUpDown` (control template + trimming risk).
   Blocker: same AOT proof as item 2.

### P2 — real friction, no flow break

4. **Session/re-login errors are discarded** in the banner (`MainView.fs`, the relogin handler drops the returned error and only re-reads `NeedsRelogin`). A post-login sync failure also becomes invisible once the banner disappears.
5. **Thumbnail retry is manual only.** `ThumbCache.Failed` stays failed for the session; the glyph click is the only retry. No automatic retry, no offline indicator.
6. **Wheel over the bounded list scroller.** The inner viewer has `maxHeight 560`; whether a wheel over a row scrolls the rows or the outer viewer is unverified. Needs a real window (not headless) or an `Avalonia.Headless` pointer-wheel test.
7. **No accessible selected state** on nav buttons, media/mode chips and the asc/desc buttons. Plain `Button` + colour only. This FuncUI build has no `AutomationProperties` helper in its DSL, and the headless tests locate buttons by `Content`, so the fix is a control change (TemplatedControl or toggle with a peer).
8. **`CultureInfo.CurrentUICulture` never follows `UiLocale`**, so Han glyph shape follows the OS culture, not the selected language. Fix lives near `I18n.Load`.

## Added late — Windows MSI uninstall discoverability (owner report, 2026-10-22)

Owner reports the MSI ships with no bundled uninstaller. Checked against the source (`packaging/windows/Product.wxs`, `scripts/publish-msi.ps1`, `scripts/test-msi.ps1`, `docs/PACKAGING.md`, `docs/REQUIREMENTS.md`).

**What is false:** there is no missing `<MajorUpgrade>`, no missing Shortcut removal, and no missing Start Menu cleanup. Removal works: `scripts/test-msi.ps1` runs `/x` for both scopes and asserts the exe is gone and user data survives. Windows Installer removal (`msiexec /x`, right-click → 解除, Windows 設定 → インストールされているアプリ) is always available for a registered MSI.

**What is actually wrong:** nothing makes the product discoverable in the GUI list and nothing ships a user-facing removal entry point.

| Gap | Evidence | Effect for the user |
|---|---|---|
| No `Icon` property / `ARPPRODUCTICON` / `.ico` asset | grep of repo: no `ARPPRODUCTICON`, no `*.ico` file anywhere | The entry in インストールされているアプリ shows the Windows default program icon. Hard to spot between other apps. |
| No `ARPNOMODIFY` policy | Product.wxs has no such property | "変更" is offered; it can only repair, so the user enters repair and gets no way to remove. |
| No Start Menu uninstall entry | Product.wxs has no uninstall shortcut | Users look for アンインストール in the Start Menu group and do not find it. |
| Product/Manufacturer text | `Name="DLsite Client"`, `Manufacturer="DlsiteClient"` | The vendor column reads `DlsiteClient`, the internal id, instead of the product owner. |
| No requirement covers this | `docs/REQUIREMENTS.md:95` only says uninstall must retain library/cache/settings/save data; nothing about discoverability | The gap is invisible to the acceptance checks, which is why the release passed. |

**Decisions needed before fixing (product, not code):**
1. App icon: does an official icon exist? If not, the fix cannot be "add an icon" — it is a design task.
2. Is a Start-Menu uninstall shortcut wanted? It is one extra `<Shortcut>` with `Target="[SystemFolder]msiexec.exe" Arguments="/x [ProductCode]"`, but it is also a one-click destructive entry sitting next to Launch.
3. Vendor label: `DLsite`? `Phil Lui`? Keep `DlsiteClient`?
4. Add `ARPNOMODIFY` so only 修復 and 削除 remain? Deciding this needs the scope-page behaviour re-checked, because a silent `/fa` repair is used by the test script and by CI.

**Fix sketch (after the decisions):** add `Icon` + `ARPPRODUCTICON` to `Product.wxs` with a packaged `.ico`, set `ARPNOMODIFY = 1`, correct `Manufacturer`/`ARPPUBLISHER`, optionally add the uninstall shortcut component, extend `docs/REQUIREMENTS.md:95` with the discoverability line, and extend `scripts/test-msi.ps1` to assert the ARP entry and the icon/shortcut exist. Cannot be verified on macOS — needs the Windows build host and a clean VM.
